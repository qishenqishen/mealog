## 定位与原则

给有餐前拍照习惯的人，用照片作为入口，整理可按人物与时间找回的生活记忆。Moment-first 为已采纳的设计方向，尚不声称其获得真实用户行为验证。

三个一等对象：时刻（既有 Meal 存储兼容咖啡、做饭过程）、人物、照片。地点是时刻属性，标签是筛选维度。自由记忆独立存储，不依附某一餐；作为轻量补充而非新的一级导航。

| 品牌隐喻 | 实际页面 | 数据 |
|---|---|---|
| Plate | 留下时刻 / 这一餐详情 | MealEntry + Photo |
| Chair | 首页人物 / 我和 TA 的餐桌 | PersonProfile + MealCompanion |
| Table | 我的餐桌 / 周月年回顾 / 每月餐桌 | 有依据的时刻集合 |

## AI 边界、成本与性能

LLM 只组织用户已留下的文字，程序计算事实。接口保留旧月度请求兼容，增加时间范围。客户端最多传 120 条按时间均匀抽样记录，超 60 KB 继续收缩；本地统计保留全量。服务端提示词上限 4096 字节、最多 12 条分布取样，输出最多 640 tokens，30 秒服务端超时，45 秒客户端超时。UI 明示抽样，年度回顾也不声称覆盖每个时刻。

当前部署模型 ID 为 `@cf/meta/llama-3.1-8b-instruct-fast`；定价页没有完全一致的模型条目，不能用相近 FP8 型号费用冒充当前成本。真实合成验收调用已返回 provider usage：438 输入 / 28 输出 tokens，服务端生成 923 ms；另一次界面验收为 491 / 52 tokens。仅作单次可用性证据，不代表质量、平均延迟或平均成本；精确定价待核实。预算公式：MAU × 人均生成次数 ×（输入 tokens × 输入单价 + 输出 tokens × 输出单价）/ 1,000,000；失败计费与 Workers/存储费用另计。

端侧 U²-Net 小模型与 ONNX Runtime 为已有实现，模型文件大小可本地核实；处理时长需区分首次加载和热运行，按真实机型采样记录中位数/P95。文档的 <2 秒、95% 是目标假设，不是本轮实测结论。餐食分类与抠图是两个任务，不能混淆。
